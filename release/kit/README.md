# Constrained recovery-kit and runtime gate

`make kit-check` creates a disposable synthetic Home from the exact selected
`VOPTRACK_IMAGE`. A real operator and a real member sign in through Console.
Trusted lineage is enrolled using the approved operator's ephemeral token;
ordinary collector authority remains retrieval-only. The gate checks committed
online preparation, exact launched configuration bytes, member/CSRF refusal,
refusal before host approval, one-use revision-bound approved browser delivery,
non-cacheable attachment headers, host-revoked approval refusal, replay refusal and exclusion of retirement
evidence/collector credentials from the kit. A disposable host-command container
also denies `fsync`/`fdatasync` through seccomp: revocation must report failure
after unlink, and delivery must be refused. This checks failure propagation, not
physical power-loss behavior. It then abruptly kills only its own
Tessera container after disabling that container's restart policy, observes that
the old receipt ages past the stale horizon and requires a new process instance
on restart. Cleanup removes only the gate's project/volumes.

The extended Console gate additionally measures two independent devices reading
content and advancing uploads during repeated supported preparation and export,
then verifies an old archive with newer retirement evidence and restores on fresh
volumes using the browser-exported kit's key/configuration. Ordinary recovery's
maintenance/offline protections remain separately exercised by `make recovery-check`.

## What this does not prove

No independent review, production throughput/latency, physical power-loss
resilience, real-phone or Swift-client operation, public-domain TLS, screen-reader
use or independent linguistic review. A running child receipt is not scheduler or
writer health. No off-machine custody, automated replication, erasure durability
SLA, guided restore or automatic matching of every historical issuer credential
is claimed. A trusted host can bypass wrappers; old uncoordinated binaries require
a planned maintenance adoption. The manifest is not an attestation against a host
that possesses the key.

### First-release fixture alignment (2026-11-08)

The operator sign-in fixture expects the accepted Home landing page (ordinary OAuth `/home` or
first-party `/`) and Manage Home navigation rather than the former Members page. It still opens `/members`
explicitly to create its synthetic non-operator fixture. Kit authority, approval,
fault, persistence and recovery assertions are unchanged.
