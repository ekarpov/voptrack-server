# Use an IP address or a private name

Home and Research can serve HTTPS at a stable IP address without a domain. Use
this setup on a network the intended phones can reach. A Research group using
this setup needs to arrange certificate trust on each participant's device for
the study website. For open recruitment, use a domain and a publicly trusted
certificate so participants can open the website without installing a root.

## 1. Set the address before starting

In the main installation guide, enter the server's actual IPv4 address, such as
`192.0.2.20`, in the address prompt, using your own address in place of the example. A
private name also works if each phone can
resolve it. Use a fixed address or reserve it in your router. Connect the phone to
the same network or an authorized VPN that can reach the address.

Choose `local` at the certificate prompt. The main guide writes that choice and
the address to `.env`. The result for the example IP looks like this:

```dotenv
VOPTRACK_DOMAIN=192.0.2.20
VOPTRACK_TLS=local
```

For a LAN or VPN installation, add a binding to the server's actual interface
address. Run this once from the installation directory after editing the example
IP. Leave router port forwarding off for a LAN-only server.

```sh
bind_ip=192.0.2.20
printf 'VOPTRACK_PUBLISH_PREFIX=%s:\n' "$bind_ip" >> .env
```

Use the same HTTPS address in the phone, browser and Voptrack setup. With the
default ports, the example is `https://192.0.2.20`. A changed IP can make saved
links and certificates stop matching.

## 2. Start the server and export its certificate

Return to the main guide and run its startup steps. On first start, Voptrack
creates a self-signed root certificate and its private key. Caddy uses that root
to issue the HTTPS certificate for the configured IP or name. Keep the root
and key in the deployment's recovery material. Export only the root certificate
for the phone. The internal Tessera certificate is for traffic inside Docker.

From the installation directory, select the Compose file already used for this
server. The offline download uses the file generated by its loader.

```sh
if [ -f compose.offline.yaml ]; then
  compose_file=compose.offline.yaml
else
  compose_file=compose.yaml
fi
```

Copy the root certificate out of the running server.

```sh
sudo docker compose -f "$compose_file" exec -T caddy cat /var/lib/voptrack-public/ca.crt </dev/null > voptrack-ca.crt
```

Show its fingerprint and make a certificate file for the iPhone.

```sh
openssl x509 -in voptrack-ca.crt -noout -subject -fingerprint -sha256
openssl x509 -in voptrack-ca.crt -outform DER -out voptrack-ca.cer
```

## 3. Check HTTPS from the host

Use the address entered during setup. These checks confirm that the certificate
matches the address and that both services answer over HTTPS.

```sh
read -r -p 'Server IP or private name: ' address
```

```sh
curl -fsS --cacert voptrack-ca.crt "https://$address/.well-known/tessera"
curl -fsS --cacert voptrack-ca.crt "https://$address/.well-known/oauth-authorization-server"
```

## 4. Trust the root on an iPhone for Safari

1. Copy `voptrack-ca.cer` from the server over your trusted SSH connection. If
   you received the file from the server owner, compare its SHA-256 certificate
   fingerprint with the fingerprint they show over a trusted channel. Transfer
   only the certificate file to your phone, for example as an attachment you
   open in Mail. Keep the private key on the server.
2. Open the certificate on the phone. Open **Settings**, tap **Profile
   Downloaded**, and follow **Install**. See [Apple's profile installation
   steps](https://support.apple.com/en-gb/102400).
3. In **Settings → General → About → Certificate Trust Settings**, enable full
   trust for **Voptrack local CA**. This adds the root to the phone's system trust.
   See [Apple's certificate trust steps](https://support.apple.com/en-us/102390).
4. Open your exact HTTPS address in Safari. Check that it opens without a
   certificate warning before entering a password or following a study link.

For Research, verify the study link in Safari and test joining with the intended
Voptrack app build. The browser test and the app test are separate checks.

## 5. Connect a Home phone through the app

A trusted Home invitation includes the root's key fingerprint, called a pin.
When the installed Voptrack app supports this flow, approving that invitation
lets the app verify Home without installing a system-wide certificate. Use the
certificate steps above if you also want the Home website in Safari.

For the owner's first phone, or an authorized replacement, stop both writers.
Creating the link signs out the owner's previous devices.

```sh
sudo docker compose -f "$compose_file" stop console tesserad </dev/null
```

Check that neither writer is running. Continue only if the command succeeds and
prints no containers.

```sh
sudo docker compose -f "$compose_file" ps --status running -q console tesserad </dev/null
```

Save the one-use link in a private file. If the command fails, resolve the
problem with both writers stopped.

```sh
umask 077
sudo docker compose -f "$compose_file" run --rm -T --interactive=false --no-deps init owner-device </dev/null > owner-device-link.txt
```

Restart the services after the link has been created successfully.

```sh
sudo docker compose -f "$compose_file" up -d --no-deps --wait tesserad console caddy </dev/null
```

Open the saved link privately in Voptrack within 24 hours. Confirm the address
and approve the key after comparing it with the owner over a trusted channel.
The certificate fingerprint and the invitation pin are calculated from different
parts of the certificate.

For members, use the Home Console invitation flow. On an app-only Home
(`VOPTRACK_CONSOLE=off`), create the link from the host and share it privately
with the accompanying sharing and rebind notice.

```sh
sudo docker compose -f "$compose_file" run --rm -T --interactive=false --no-deps init invite </dev/null > member-invitation.txt
```
