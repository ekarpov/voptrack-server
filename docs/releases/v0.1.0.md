# Voptrack Server v0.1.0 preparation

This is the preparation report for the first Home and Research release. It is
not an announcement that downloads are already public. Check GitHub Releases
for the published release and use its exact source, images and installation files.

## What is included

Home and Research use the same server code with separate product defaults and
matching installation downloads. Both use Tessera v0.1.0, public commit
`6367a78c8ee89b97acbb14c8680b22d961bac8fb`. No GitHub credentials are needed to
fetch that dependency. Start with fresh storage; alpha/RC data is not supported.

Home offers household sharing and member management. Research offers study
setup, consent, participant management, collection monitoring and exports.
Neither first-release website offers Saved views.

## Independent review

The release work received a separate review of building, packaging, installation
and recent integration changes. It found a discarded image-build result, missing
dependency notices, obsolete private-source instructions and an overly broad
callback-path test. The preparation changes retain build outputs, include notices,
use public downloads and compare the exact callback address. Product downloads
also fix the correct Home or Research setting instead of accepting a generic default.

The runtime base is Alpine 3.24.4, pinned by digest. Alpine lists support for
3.24 through June 2028; the previous 3.21 base reached its listed end date on
1 November 2026. See [Alpine's release table](https://alpinelinux.org/releases/).

Installation commands and scenario provisioning disable terminal input when no
input is needed, so pasted commands for the next step cannot be consumed by a
short-lived Docker command.

## Test record

The earlier Tessera v0.1.0 integration candidate passed all 23 full-suite gates.
Each prepared download includes `qualification.txt` with the exact source commit,
Tessera pin, full-suite results and tested base-image identity. Its `release.json`
identifies the actual product image and platform. Product images are separately
started and checked before delivery. These are preparation results; public-host
and real-app acceptance must still be recorded before publication. Earlier test
results are not transferred to a new commit merely because its code looks similar.

## Limits and remaining release steps

The guides cover source builds and prepared images on Linux x86-64. Do not
advertise native ARM acceptance without testing that platform. Local synthetic
checks do not establish public DNS/TLS on a user's host, real phone behavior,
independent backup custody or a complete privacy audit.

The illustrative tracks catalog still reports four unresolved annotation-key
questions. Its append-only entries have not been rewritten to hide them. They
are separate from the release gate and need vocabulary-owner disposition.

Before publication, finish public-tree/license review, verify fresh-host installs
for both products and paths, make the two GitHub image packages public, attach
matched downloads and checksums, and test anonymous downloads. Keep release files
unchanged after publication. Existing app-facing upgrades still need compatibility
confirmation and at least two weeks' notice. Frozen App Review demos remain on
rc.4, untouched. Preparing this release does not deploy or upgrade them.
